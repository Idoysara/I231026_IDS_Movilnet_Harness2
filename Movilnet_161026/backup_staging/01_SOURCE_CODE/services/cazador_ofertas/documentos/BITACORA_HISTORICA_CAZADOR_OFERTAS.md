## 🧭 CAPÍTULO 1: FUNDAMENTOS DE NEGOCIO, ACTORES Y LA REGLA SUPREMA DE CERO ALUCINACIÓN B2C

### 1.1. Visión Tripartita del Ecosistema
El proyecto **Cazador de Ofertas** se concibió para alinear los intereses de tres actores clave en Venezuela:
1. **Abonados Móviles Movilnet (Consumidores B2C):** Acceso inmediato a descuentos georreferenciados en bolívares (VES), con navegación gratuita (**Zero-Rating**, sin consumo del saldo de megas) y cobro opcional de micro-suscripciones VIP contra saldo prepago/pospago (`0416`/`0426`).
2. **Comercios Aliados (Merchants B2B):** Canal de afluencia masiva de clientes presenciales sin costes publicitarios fijos. Blindaje contra capturas de pantalla falsas mediante códigos TOTP rotativos cada 60 segundos.
3. **Operadora Telco Movilnet:** Monetización del tráfico a través de un split del 20% en Carrier Billing, retención de abonados (*anti-churn*) y posicionamiento de marca soberano.

### 1.2. Regla Suprema Inviolable: Cero Alucinación B2C
Queda terminantemente prohibido generar, proponer o simular ofertas comerciales que no tengan un respaldo físico estricto:
* Toda oferta devuelta por el sistema debe pertenecer a un comercio activo registrado en la tabla `comercios`.
* Debe poseer coordenadas GPS verificadas (lat/lon en WGS84) y `stock_disponible > 0`.
* Si un usuario busca un rubro sin promociones activas (ej: "zapatos de golf en Petare"), el sistema declara con total honestidad que no hay coincidencias y ofrece el radar en vivo sin inventar descuentos ficticios.

## 🧮 CAPÍTULO 2: MATRIZ COMPLETA DE ENTRADAS, ALGORITMOS, BASES DE DATOS Y SALIDAS (I/O PIPELINE)

Cada operación del sistema obedece a un pipeline estricto de 4 fases:

```
[ INPUTS ] ──► [ PROCESAMIENTO / ALGORITMO ] ──► [ PERSISTENCIA / DB ] ──► [ OUTPUTS ]
```

### Tabla Resumen de los 14 Algoritmos Principales:
1. **Radar Geoespacial Haversine:** Inputs: $(lat, lon, r)$ $\to$ Poda Bounding Box + Haversine esférico ($R=6,371\text{km}$) $\to$ DB: `comercios` $\to$ Output: 3 Anillos concéntricos (<500m, 500m-1km, 1km-3km).
2. **Bóveda Dinámica TOTP 60s:** Inputs: $(UUID, MSISDN, K, t)$ $\to$ $T_{\text{step}}=\lfloor t/60 \rfloor$, $\text{HMAC-SHA256}$ $\to$ Output: Código `QRO-...` rotativo.
3. **Quema Anti-Replay en Caja:** Inputs: $(UUID, \text{firma})$ $\to$ $\text{Fingerprint} = \text{SHA256}(UUID \parallel \text{firma})$ $\to$ DB: `boveda_hashes_quemados` $\to$ Output: Canje irreversible.
4. **Guarda de Margen Bruto $\ge 35\%$:** Inputs: $(P_{\text{oferta}}, C_{\text{directo}})$ $\to$ $\frac{P - C}{P} \ge 0.35$ $\to$ DB: Check Constraint $\to$ Output: Publicación válida o HTTP 422.
5. **Split Transaccional 20/80:** Inputs: $M_{\text{ves}}$ $\to$ $M_{\text{telco}} = M \times 0.20$, $M_{\text{comercio}} = M \times 0.80$ $\to$ DB: `transacciones_billing`.
6. **Cuota Anti-Acaparamiento:** Inputs: $MSISDN$ $\to$ Count(cupones activos) $\le 3$ $\to$ DB: `cupones` (estado='RECLAMADO').
7. **FSM de Ciclo de Vida:** $\text{RECLAMADO} \to \text{CANJEADO}$ (Estado final inmutable).
8. **Magic Link HMAC Zero-Rating:** Inputs: $(MSISDN, exp, oferta)$ $\to$ Firma HMAC + Headers `X-Movilnet-Zero-Rating`.
9. **Carrier Billing Idempotente:** Inputs: $(MSISDN, Monto, IdempotencyKey)$ $\to$ Hash SHA-256 único anti-duplicados.
10. **Decremento Atómico de Stock:** `UPDATE ofertas SET stock_disponible = stock_disponible - 1 WHERE stock_disponible > 0`.
11. **Memoria FTS5 Presupuestada:** Consultas SQLite FTS5 BM25 podadas a $\le 450$ tokens.
12. **Caché Offline PWA:** Stale-While-Revalidate en `sw.js`.
13. **Gateway Omnicanal N8N:** Normalizador polimórfico de payloads multicanal.
14. **Candado Exclusividad Telco:** Validación de prefijos oficiales `0416` / `0426`.

### 8.2. Desglose Técnico de los 11 Nodos
1. **`Webhook WhatsApp` (`node-webhook-wa`):**
   * Path: `/webhook/cazador-whatsapp` | Método: `POST`.
   * Compatible con Meta WhatsApp Business Cloud API, Evolution API o Whapify.
   * Captura tanto mensajes de texto (`messages[0].text.body`) como pines de ubicación GPS compartida (`messages[0].location`).
2. **`Webhook Telegram` (`node-webhook-tg`):**
   * Path: `/webhook/cazador-telegram` | Método: `POST`.
   * Vinculado con la Telegram Bot API (`setWebhook`).
   * Captura comandos de chat (`message.text`) o pines de ubicación nativos de Telegram (`message.location.latitude`, `message.location.longitude`).
3. **`Webhook PWA Event` (`node-webhook-pwa`):**
   * Path: `/webhook/cazador-pwa` | Método: `POST`.
   * Permite a la aplicación web progresiva enviar consultas programáticas o disparar eventos de telemetría.
4. **`Normalizador Omnicanal` (`node-normalizador` - Code Node JavaScript):**
   * Extrae de forma polimórfica remitente, texto y coordenadas GPS según la estructura del payload entrante.
   * Aplica regex de normalización para transformar números con código de país (`58416...` o `+58 416...`) al estándar venezolano `0416...` / `0426...`.
   * Inyecta la bandera booleana `es_movilnet: true/false`.
5. **`¿Es Abonado Movilnet?` (`node-filtro-movilnet` - IF Node):**
   * Evalúa la condición booleana `{{ $json.es_movilnet }} == true`.
   * Si es `false`, bifurca hacia el nodo de rechazo.
6. **`Rechazo Operadora Ajena` (`node-rechazo-no-movilnet` - Respond to Webhook):**
   * Retorna `HTTP 403 Forbidden` con mensaje informativo y empático:
     *"👋 ¡Hola! El Cazador de Ofertas y el beneficio de navegación Zero-Rating (sin consumo de datos) es exclusivo para líneas Movilnet (0416 y 0426)."*
7. **`Invocar Cazador Core API (:8030)` (`node-cazador-api` - HTTP Request Node):**
   * Despacha `POST http://localhost:8030/api/deflector/n8n`.
   * Payload: `{ canal, remitente, mensaje, ubicacion_lat, ubicacion_lon }`.
   * El Core API ejecuta en submilisegundos:
     - Radar Haversine esférico y clasificación en 3 anillos.
     - Cero Alucinación B2C: Búsqueda estricta en el catálogo auditado.
     - Generación de Magic Link firmado con HMAC-SHA256 y validez de 24 horas.
     - Inyección de cabeceras oficiales de Zero-Rating: `X-Movilnet-Zero-Rating: active`.
8. **`Enriquecedor de Respuesta` (`node-formateador` - Code Node JavaScript):**
   * Mapea los metadatos de respuesta del motor central con los identificadores originales del remitente.
   * Genera el parámetro `telegram_webapp_url` para disparar la PWA en el visor nativo de Telegram.
9. **`Switch Canal Saliente` (`node-switch-canal` - Switch Node):**
   * Regla de ruteo por campo `canal`:
     - Regla 0: `whatsapp`
     - Regla 1: `telegram`
     - Regla 2: `pwa`
10. **`Respuesta WhatsApp Webhook` (`node-resp-wa`):**

### 14.1. Fundamentación del Protocolo REA (Reverse Engineer Anything)
A partir de los hallazgos de la investigación de benchmark del Capítulo 13, se aplicó la disciplina formal de **Ingeniería Inversa Limpia (Clean-Room Software Engineering)**:
1. **Separación de Cámaras (Chinese Wall):** Se capturaron las evidencias funcionales y especificaciones de comportamiento de los líderes de mercado sin copiar código propietario.
2. **Extracción Forense de Patrones:**
   * **Protocolo de Lectura Rápida QR en Caja:** Deconstrucción del flujo de Cashea en cajas venezolanas (lectura en <0.5s bajo iluminación deficiente de locales comerciales mediante payloads QR ultracompactos $\le 45$ caracteres alfanuméricos).
   * **Motor de Reglas Condicionales:** Deconstrucción de Voucherify y Medusa.js para promociones avanzadas (2x1 / Buy X Get Y, Happy Hour diurno para restaurantes, descuento por volumen escalonado y consumo mínimo).
   * **Centinela Anti-Colusión Cajero-Abonado:** Blindaje contra la re-presentación del mismo cupón por complacencia del cajero mediante ventanas de tolerancia de 30 segundos y quema atómica de huella.

### 14.2. Especificación Técnica de los Componentes Clean-Room
1. **`PromotionRuleType` y `EvaluationContext`:**
   * Soporta 5 tipos de reglas: `PERCENTAGE`, `BUY_X_GET_Y`, `HAPPY_HOUR_WINDOW`, `TIERED_VOLUME`, `MIN_BASKET_AMOUNT`.
   * **Cumplimiento Invariante II Dinámico:** Tras computar el descuento efectivo, el motor evalúa:
     $$\text{Margen Post-Promo} = \frac{P_{\text{final}} - C_{\text{directo}}}{P_{\text{final}}} \ge 0.35$$
     Si la regla reduce el margen por debajo del 35%, se lanza `DomainInvariantViolationError`, protegiendo la solvencia del comerciante.
2. **`CompactQRCodec` (Protocolo QR Ultracompacto tipo Cashea):**
   * Estructura: `SOF-V1:{deal_id_tail}:{msisdn_tail}:{totp_token}:{sig8}`.
   * Longitud promedio: 36 a 42 caracteres (versus >180 caracteres de URLs completas).
   * Verificación bidireccional contra TOTP y firma criptográfica HMAC-SHA256 truncada a 8 caracteres hexadecimales.
3. **`CashierAntiCollusionSentinel`:**
   * Bóveda local en memoria y persistente con marca de tiempo y comprobación de ventana de colusión (rechazo de dobles canjes en $<30$ segundos).

### 14.3. Integración en `CazadorApplicationService`
